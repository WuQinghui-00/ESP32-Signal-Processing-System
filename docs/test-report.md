# ESP32 信号处理系统 真机测试报告

## 1. 测试概述

本报告记录 ESP32 信号处理系统（`fae-improvement` 分支）在开发板上的验证结果，覆盖信号链路准确性、网络可靠性、Web/MQTT 功能与真机故障定位修复。

## 2. 测试环境

| 项目 | 配置 |
|---|---|
| 开发板 | ESP32（CP210x USB 串口，COM19） |
| 信号发生器 | Rigol DG1032（High-Z 负载，正弦 50~400Hz，Vpp 0.5~2V，偏置 1.65V） |
| 示波器 | Rigol DHO4804（CH2，DC 耦合） |
| 网络 | 手机热点（WPA3，RSSI -43~-62dBm） |
| MQTT | broker.emqx.io，主题 `/esp32/signal/freq`，QoS1 |
| 固件版本 | `161d062`（含 P2/P3 全部功能与 3 个真机修复） |

## 3. 测试项目与结果

### 3.1 编译与烧录

✅ 通过。`idf.py build` 正常，`idf.py -p COM19 flash monitor` 烧录成功。

### 3.2 采样率校准（P2-1）

✅ 通过。实测采样率稳定 **1007 S/s**（目标 1000，误差 <1%）。

### 3.3 FFT 频率准确性（P2-3）

✅ 通过。128 点 FFT 频率分辨率 7.8125Hz，五档测试全部落在 ±1 bin 内：

| 发生器设定 (Hz) | FFT 报频 (Hz) | 对应 bin | 偏差 |
|---|---|---|---|
| 50 | 47 | 6（46.9） | -3 |
| 100 | 102 | 13（101.6） | +2 |
| 200 | 203 | 26（203.1） | +3 |
| 300 | 297 | 38（296.9） | -3 |
| 400 | 398 | 51（398.4） | -2 |

### 3.4 幅度线性（P2-3 幅值输出）

✅ 通过。200Hz 下幅度 0.5/1/2 Vpp，FFT 幅值严格线性：

| 设定 (Vpp) | FFT amp | 比值 |
|---|---|---|
| 0.5 | ~8,800 | 1.00 |
| 1 | ~17,500 | 1.99 |
| 2 | ~35,700 | 4.06 |

注：amp 换算电压约为设定值的 44~45%（固定比例，来自窗函数增益与 ADC 标定系数，非线性无异常）。

### 3.5 Web 功能（P2-5 / P3-7）

✅ 通过。`http://<IP>/` Canvas 频谱曲线与峰值标记正常；`/api/status`、`/api/metrics` 秒回 JSON。

### 3.6 MQTT 可靠性（P2-6 / P3-2 / P3-3）

✅ 通过。长时间运行发布 2400+ 条 QoS1 消息，除断线瞬间外 100% ACK；断线期间缓存最新状态，重连后自动补发（`Resent cached state`）。

### 3.7 WiFi 断网/恢复（P3-1 / P3-3）

✅ 通过。关闭热点后：

- 退避重连：`reconnect #1 in ~1087 ms` → `#2 in 2171 ms` →（延时翻倍，±20% 抖动）
- 断线缓存：每 2 秒 `MQTT offline, cached latest state`
- 热点恢复后自动重连（Got IP）→ MQTT 重连 → 缓存帧补发 → 恢复正常发布
- 统计计数递增（`disconnects` / `attempts`）

### 3.8 长时间稳定性

✅ 通过。连续运行 90+ 分钟无异常，堆余量约 170KB。

## 4. 真机故障案例（发现 → 定位 → 修复 → 验证）

### 案例 1：`/spectrum/data` 接口卡死

- **现象**：`/api/status` 正常，`/spectrum/data` 一直转圈不返回。
- **定位**：对比两接口后怀疑 handler 栈超限；检查 httpd 默认任务栈 4096，频谱 handler 局部缓冲 2.3KB + 浮点 printf 栈使用超限。
- **根因**：httpd 任务栈溢出，任务崩溃导致请求挂死。
- **修复**：`config.stack_size = 8192`（注意 IDF 5.x 字段名为 `stack_size`）。
- **验证**：重烧后接口秒回 JSON。

### 案例 2：Web 页面频谱曲线不显示

- **现象**：页面数据能更新但 Canvas 无曲线，Console 报 `Uncaught SyntaxError: Unexpected end of input`。
- **定位**：查看页面源码发现 HTML 为单行传输，JS 中 `//` 行注释把该行剩余代码全部注释掉，`draw()` 未闭合。
- **根因**：C 字符串拼接的 HTML 无换行，`//` 注释在单行中吞掉整段脚本。
- **修复**：`//` 注释改为 `/* */` 块注释。
- **验证**：Node 对“单行 JS”做语法检查复现同一报错，修复后通过；重烧后曲线正常绘制。

### 案例 3：任务看门狗报警

- **现象**：每 5 秒打印 `task_wdt: IDLE1 (CPU 1)`，CPU1 被 `dac_out` 任务占用。
- **定位**：DAC 输出任务为忙等循环（`esp_rom_delay_us`），优先级 5 且永不阻塞，饿死 IDLE1。
- **修复**：改用 esp_timer 周期定时器驱动 DAC 输出，任务不再占用 CPU。
- **验证**：重烧后看门狗报警消失，波形输出正常。

## 5. 测试结论

- 信号链路（采样 → 去直流 → FFT → 峰值）频率与幅值均通过仪器交叉验证。
- 网络可靠性（退避重连、缓存补发、QoS1 统计）在真实断网场景下工作正常。
- Web 与诊断接口功能完整。
- 真机测试发现并修复 3 个编译期不可见的问题，验证了真机测试的必要性。
